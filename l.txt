La génération d'images satellites à partir de photos prises au niveau du sol (photos perspectives) est un domaine de recherche actif en vision par ordinateur, souvent désigné sous le terme de synthèse inter-vues (cross-view image synthesis).

Il est important de distinguer la réalité technique actuelle des capacités grand public :

1. La complexité de l'exercice
Générer une vue satellite réaliste à partir d'une photo prise à hauteur d'homme est extrêmement difficile pour plusieurs raisons :

Différence de perspective : Une photo au sol montre des façades et des objets proches, tandis qu'une image satellite offre une vue verticale (nadir) couvrant une zone bien plus large.

Occlusions : La photo au sol contient des informations invisibles depuis le ciel (dessous des arbres, intérieurs de bâtiments, objets cachés par des structures), et inversement.

Comblement d'information : L'IA doit "inventer" ou déduire ce qui n'est pas visible dans la photo originale pour reconstruire la zone environnante vue du ciel.

2. État de la recherche
Des modèles académiques ont été développés pour résoudre ce problème, principalement pour faciliter la géolocalisation croisée (identifier où une photo a été prise en la comparant à une base de données satellite) :

Réseaux antagonistes génératifs (cGAN) : Des architectures comme celles présentées dans les recherches sur la synthèse "Street-to-Satellite" utilisent des réseaux capables d'apprendre la correspondance entre des paires d'images alignées.

Modèles de diffusion : Des approches plus récentes (comme CrossViewDiff) utilisent des modèles de diffusion pour générer des images réalistes en intégrant des modules d'estimation de profondeur et de contrôle structurel pour mieux gérer le fossé entre les points de vue.

3. Applications existantes
Il n'existe pas actuellement de solution "grand public" magique qui transformerait instantanément n'importe quelle photo de vacances en une vue satellite précise et fidèle au réel :

Simulation et cartographie : Certains modèles, comme Seamless Satellite-image Synthesis (SSS), sont capables de générer des images de style satellite à partir de cartes vectorielles (données géographiques structurées) plutôt qu'à partir de photos brutes. Cela permet de créer des environnements pour des simulateurs de vol ou des jeux vidéo.

Extraction de données : Des logiciels professionnels (SIG) permettent d'extraire des empreintes de bâtiments ou des caractéristiques 3D à partir d'images aériennes, mais cela va généralement dans le sens inverse (du ciel vers le sol).

En résumé, si des modèles expérimentaux existent pour effectuer cette transformation dans le cadre de recherches sur la géolocalisation, ils ne permettent pas de générer des cartes satellites fiables à partir de n'importe quelle photo de manière universelle. Ces outils sont principalement conçus pour aider les algorithmes à comprendre que deux images très différentes représentent en réalité le même endroit.

"""Rend une image comme si on etait IMMERGE dans un espace hyperbolique.



Inspire de HypeVPR (arXiv:2506.04764) : on utilise le modele de la BOULE DE

POINCARE et la carte exponentielle a l'origine (Eq. 4 de l'article)



    exp_0^c(v) = tanh(sqrt(c) * ||v||) * v / (sqrt(c) * ||v||)



Ici on l'applique aux COORDONNEES SPATIALES de l'image (et non aux

descripteurs) pour repondre a la question : "si on me placait dans un espace

non euclidien (hyperbolique) la ou la photo a ete prise, comment verrais-je

l'espace autour de moi ?".



Intuition geometrique :

  - L'observateur est au CENTRE du disque de Poincare.

  - Un point situe a une distance hyperbolique rho droit devant lui apparait

    au rayon  R = tanh(sqrt(c) * rho)  dans le disque.

  - tanh sature en 1 : tout l'espace infini est comprime dans un disque fini.

    Les objets proches restent au centre, les objets lointains se tassent

    vers un HORIZON circulaire (le bord). Les lignes droites deviennent des

    arcs : c'est l'aspect caracteristique d'un espace a courbure negative.



Usage :

    python to_hyperbolic.py <image.png>

    python to_hyperbolic.py <image.png> -c 2.5 -s 900 -o sortie.png

    python to_hyperbolic.py <image.png> --show

"""



import argparse

import sys

from pathlib import Path



import numpy as np

from PIL import Image





def load_rgb(path: Path) -> np.ndarray:

    with Image.open(path) as im:

        return np.asarray(im.convert("RGB"), dtype=np.float32)





def bilinear_sample(img: np.ndarray, xs: np.ndarray, ys: np.ndarray) -> np.ndarray:

    """Echantillonnage bilineaire de img aux coordonnees (xs, ys) en pixels.



    xs, ys : tableaux de meme forme. Renvoie un tableau (..., 3).

    Les coordonnees hors image renvoient du noir.

    """

    H, W = img.shape[:2]

    valid = (xs >= 0) & (xs <= W - 1) & (ys >= 0) & (ys <= H - 1)



    x0 = np.clip(np.floor(xs).astype(int), 0, W - 1)

    y0 = np.clip(np.floor(ys).astype(int), 0, H - 1)

    x1 = np.clip(x0 + 1, 0, W - 1)

    y1 = np.clip(y0 + 1, 0, H - 1)



    wx = (xs - x0)[..., None]

    wy = (ys - y0)[..., None]



    Ia = img[y0, x0]

    Ib = img[y0, x1]

    Ic = img[y1, x0]

    Id = img[y1, x1]



    top = Ia * (1 - wx) + Ib * wx

    bot = Ic * (1 - wx) + Id * wx

    out = top * (1 - wy) + bot * wy

    out[~valid] = 0.0

    return out





def hyperbolic_view(img: np.ndarray, size: int, c: float,

                    draw_horizon: bool = True) -> np.ndarray:

    """Construit la vue immersive dans le disque de Poincare.



    Rendu par "inverse mapping" : pour chaque pixel de sortie a rayon R dans

    le disque (R < 1/sqrt(c)), on retrouve la distance rho dans la scene via

    la carte logarithmique (inverse de exp), puis on echantillonne l'image.

    """

    H, W = img.shape[:2]

    sqrt_c = np.sqrt(c)

    bound = 1.0 / sqrt_c  # rayon du disque de Poincare



    # grille de sortie normalisee dans [-bound, bound]

    lin = np.linspace(-bound, bound, size)

    ux, uy = np.meshgrid(lin, lin)

    R = np.sqrt(ux ** 2 + uy ** 2)

    theta = np.arctan2(uy, ux)



    inside = R < bound * 0.999

    Rn = np.clip(R * sqrt_c, 0.0, 1.0 - 1e-6)  # R normalise dans [0,1)



    # inverse de R = tanh(sqrt_c * rho) -> rho = atanh(Rn) / sqrt_c

    rho = np.arctanh(Rn) / sqrt_c



    # rho=0 au centre -> bord de la scene a rho_max. On normalise pour que le

    # bord du disque corresponde au coin de l'image (rho_max calibre).

    rho_max = np.arctanh(0.999) / sqrt_c

    frac = np.clip(rho / rho_max, 0.0, 1.0)  # fraction radiale dans l'image [0,1]



    # direction (cos, sin) ; on etire sur le rectangle de l'image

    cx, cy = (W - 1) / 2.0, (H - 1) / 2.0

    xs = cx + frac * np.cos(theta) * cx

    ys = cy + frac * np.sin(theta) * cy



    out = bilinear_sample(img, xs, ys)

    out[~inside] = 0.0  # au-dela de l'horizon : le vide



    if draw_horizon:

        ring = (np.abs(R - bound) < bound * 0.004)

        out[ring] = np.array([60, 60, 60], dtype=np.float32)



    return np.clip(out, 0, 255).astype(np.uint8)





def main() -> int:

    parser = argparse.ArgumentParser(

        description="Rend une image comme vue depuis un espace hyperbolique "

                    "(modele de la boule de Poincare).")

    parser.add_argument("image", type=Path, help="Image PNG (ou autre) a transformer")

    parser.add_argument("-c", "--curvature", type=float, default=2.5,

                        help="Force de la courbure (defaut: 2.5 ; plus grand = "

                             "espace plus 'replie' sur lui-meme)")

    parser.add_argument("-s", "--size", type=int, default=900,

                        help="Taille (cote) de l'image de sortie carree (defaut: 900)")

    parser.add_argument("-o", "--output", type=Path, default=None,

                        help="PNG de sortie (defaut: <image>_hyperbolic.png)")

    parser.add_argument("--no-horizon", action="store_true",

                        help="Ne pas dessiner le cercle d'horizon")

    parser.add_argument("--show", action="store_true",

                        help="Affiche le resultat (necessite matplotlib)")

    args = parser.parse_args()



    if not args.image.exists():

        print(f"Image introuvable: {args.image}", file=sys.stderr)

        return 1

    if args.curvature <= 0:

        print("--curvature doit etre > 0", file=sys.stderr)

        return 1



    out_path = args.output or args.image.with_name(args.image.stem + "_hyperbolic.png")



    print(f"Chargement de {args.image} ...")

    img = load_rgb(args.image)



    print(f"Rendu hyperbolique (c={args.curvature}, taille={args.size}) ...")

    view = hyperbolic_view(img, args.size, args.curvature,

                           draw_horizon=not args.no_horizon)



    Image.fromarray(view).save(out_path)

    print(f"Vue hyperbolique enregistree -> {out_path}")



    if args.show:

        import matplotlib.pyplot as plt

        fig, (a, b) = plt.subplots(1, 2, figsize=(13, 6.5))

        a.imshow(img.astype(np.uint8))

        a.set_title("Image d'origine (euclidienne)")

        a.axis("off")

        b.imshow(view)

        b.set_title("Vue depuis l'espace hyperbolique")

        b.axis("off")

        fig.tight_layout()

        plt.show()



    return 0





if __name__ == "__main__":

    raise SystemExit(main())

Méthode	Volume (arrondissement)	Qualité géométrique
pano-crop (360 recadrés vers le centre)	~quelques dizaines/centaines	propre, chaque vue regarde le centre
flat (perspectives groupées par lieu)	plusieurs milliers	vues dans des directions variées

Mode both — comment ça marche
Pour chaque carré de 25 m, dans le même dossier places/place_NNNNNN/ :

pano_<cap>.jpg : jusqu'à --views panoramas recadrés vers le centre (quand des 360 existent) ;
